Everything described under v0.6.0, which is the first version of this work that
actually publishes. v0.6.0, v0.6.1 and v0.6.2 were tagged and every build failed
before the release step, so none of them exists as a download. Nothing to
reindex.

- All three failures came from one check on this repository's own release notes,
  never from the product. It verified that every note names a real git tag,
  reading that from whatever tags the checkout happened to carry: none by
  default, and exactly one — the version being built — when the checkout is a
  tag. `fetch-tags` cannot fix it either, because combined with a tag ref it
  makes git fetch the commit and the tag to the same place and the checkout
  fails outright. The check now runs where the tag list is real, a developer's
  clone, and skips with a reason where it is not.

**`kivgraph serve --introspection` publishes the complete MCP tool catalog
before an index exists.** It is for the inspectors and registries that read
tool definitions to score a server and have nothing to read when the handshake
publishes nothing. Nothing stored changed shape, and normal `serve` is
unchanged.

- **It lists tools; it does not create one.** Starting it publishes no
  generation, fabricates no empty graph and relaxes no disk-space check. Every
  read tool it lists answers `INDEX_NOT_READY` until a generation exists —
  `graph_status` reports an empty graph rather than refusing, as it always did
  — and `index_project` stays behind its consent gate, answering
  `PERMISSION_REQUIRED` without approval.
- **The definitions are the served ones**, registered from the same place a
  published server registers them, so what an inspector scores is what a client
  gets. A second schema-only surface would have drifted from the first, and the
  score would have described a server nobody runs.
- **The handshake still says the graph is missing.** What a client is told
  depends on whether a generation is published, never on this flag: telling it
  otherwise would route work to tools that cannot answer instead of to the
  command that repairs them.
- **Only `serve` has it**, and a `serve` given it answers from its own process
  instead of relaying to a running daemon — the catalog being asked about is
  its own, and a daemon nobody asked for introspection would have answered a
  different question.
